# 一、现状分析报告：InforCenter PLM (PLMSOFT)

> 分析对象：`E:/tedri_project/dev/PLM_Clone/PLMSOFT`（约 32,000 个文件）
> 分析方法：目录结构勘察、声明式元数据（`.model/.dic/.schema/.page/.menu/.life/.setting/.cmdsql`）解析、
> 程序集清单、配置项语义还原、菜单/动作链重建。全程只读，未修改原系统任何文件。

## 1. 系统身份与技术栈

| 项 | 结论 | 证据 |
|---|---|---|
| 产品 | 山东山大华天软件 **InforCenter Platform Enterprise** | `Server/Config/ProductInfo.dic` |
| 版本 | 平台 8.11.2，产品 9.4 | `Server/Config/SystemInformation.dic` |
| 服务端形态 | **不是 C++**，而是 **.NET Framework 4.8 + ASP.NET WebForms + .asmx WebService + WCF/RPC** | `Server/Web.config`（`targetFramework="4.8"`）、`Server/Global.asax`、`Server/Bin/Hoteam.InforCenter.*.dll` |
| 进程模型 | 两层：`WebService`(IIS) + `BusinessService`(独立进程，默认 127.0.0.1:8890，WCF/RPC) | `Server/Global.asax.cs`、`Config/Service.setting`、`Config/ServiceAddr.setting` |
| 数据库 | 多方言（MSSQL/Oracle/MySQL/达梦，`.cmdsql` 按方言分流） | `InforCenter/*/Config/DBConfig/*.cmdsql`、`Bin/DmProvider.dll` |
| 中间件 | Redis（哨兵/主从）、MongoDB、Elasticsearch、RabbitMQ/Kafka(EventBus)、WebSocket | `Config/{Redis,MongoDB,ElasticSearch,RabbitMQ,EventBus,WebSocket}.setting` |
| 前端 | WebForms 服务端渲染 + 自研 JS 框架（约 470 个 js）+ 第三方控件（AutoVue、DSView ActiveX、Stimulsoft 报表） | `Server/Base`、`Server/InforCenter/Ctrls`、`Config/AutoVue.gui` |
| C++ 相关部分 | 仅存在于 **CAD 集成/格式转换侧**：`DistributedFileServer/CommandService`（`.trans` 转换脚本 5896 个）、`FileConversionService`、CAD 命令服务 dll | `DistributedFileServer/`、`InforCenter/Ctrls/*.CAB` |

**结论**：旧系统的可维护性问题并非来自 C++，而来自
① 元数据以数千个 XML 散落在目录中，无版本、无校验、无灰度；
② 业务规则被写进 `.dll` 与 `.js` 的字符串方法名（`JSMethod`/`WebMethod` 反射调用），编译期无法发现错误；
③ 状态名作为**数据库字面量**硬编码进 SQL；④ 前后端强耦合于 WebForms 控件树。

## 2. 元数据驱动体系（本系统的"内核源码"）

功能不是硬编码页面，而由七层声明式文件拼装：

```
Apps.app            模块组合根（挂载/裁剪业务包）
  └─ *.nav          一级/二级导航（WorkGroup.nav / NavigationItems.nav）
      └─ *.link     页签组（属性/文件/历史/流程/权限/日志…）
          └─ *.page  页面布局 + 控件 + 生命周期脚本
              ├─ *.view / *.listview   数据视图（列、查询条件）
              ├─ *.menu                工具条/右键 = WebAction 动作编排
              │     └─ ActionChecker（权限）+ WebMethod（服务）+ JSMethod（前端）+ WebMessageAndLogger（消息与审计）
              └─ *.generator           页面/代码生成模板
数据层：*.model（对象模型）→ *.schema（DDL 快照）→ *.cmdsql（方言 SQL）
配套：*.dic（多语言/枚举/页面字典）、*.setting（键值参数）、*.plugin（IoC 注册）、*.service（服务契约）、
      *.init（程序集装配）、*.life/*.lifestate（生命周期状态机）、*.flowplugin/*.flowactor（工作流扩展点）、
      *.coderule（编码规则）、*.version（版本号格式）
```

规模：`.model` 约 875 个（EntityType ≥ 688、其余为 LinkType）；`.page` 2,295 个；`.menu` 319 个；`.dic` 5,084 个。

## 3. 元模型（比功能更重要的资产）

### 3.1 类层次

```
ENTITY（抽象根：EID/ECODE/ENAME/STATEID/EVERSION/EUID/CREATE*/OWN*/ECOMPANYID…）
├─ PLMENTITY（+DESCRIPTION/WORKFLOWSTATE/RELEASEDATE/POSITION）
│  ├─ PLMENTITYITERATION（+CURITERATION/CHECKOUTUSER/CHECKOUTSTATE/CHECKOUTDATE）
│  │  ├─ PSEITEMMASTER → PSEITEM（零部件）
│  │  ├─ DOCMASTER → DOCDATASET（图文档）
│  │  ├─ PROUTEMASTER → PROUTE（工艺路线）
│  │  └─ REPORTMASTER（工艺卡片）
│  ├─ PROJECTENTITY → PROJECTMASTER → PROJECT
│  └─ CMAPPLY/CMNOTICE/CMPROBLEM/PMTASK/QPROBLEM/OPERATIONSPECIFICATION…
├─ PLMFORM（类型子模型基类：EID/ESTATION/ECOMPANYID）
│  ├─ PSEITEMBASEFORM → PSEITEMPARTFORM/PRODUCTFORM/STANDARDFORM/FIXTUREFORM…
│  ├─ PMTASKBASEFORM → PMNORMALTASKFORM/PMAPPLYTASKFORM…
│  └─ DOCBASEFORM / CMAPPLYBASEFORM …
└─ CLASSIFYENTITY / CODERULE / MSEOBJ …

LINK（抽象）→ PLMLINK → PSEBOMLINE / PSEITEMRELATION / CMRELATION / MSERELA / PROJECTFOLDERLINK …
```

### 3.2 三种字段语义（必须在新技术栈中保留）

1. **值类型可插拔**：`Type="CodeValue"`、`StateValue`、`VersionValue`、`SubDataModelValue`、
   `MultiUserValue`、`PositionValue`、`FileUploadValue`、`ThickRuleValue`… 实测 31 种，
   由 `.plugin`（`ObjectValueType.plugin`）注册到容器，元数据只写类型名。→ 对应 Java 的**策略枚举 + Spring Bean 注册表**。
2. **类型多态**：`SubDataModelValue` + `ExtendProperty1=<类型子模型基类>` + `FORMID` 指向子模型记录，
   实现"零件/产品/标准件/工装/模具"共用一张主表 + 各自表单/字段。→ 对应 JPA `@Inheritance(JOINED)` 或单表 + 类型列。
3. **能力位 `ModelGroups`**：一行字符串决定该模型是否参与 `SampleQuery / AdvanceQuery / CreatePermission /
   ActionRuleConditionObjectType / CompanyRuleObjectType / DataIsolationModel`。→ 这是"零代码控制权限能力"的关键。

### 3.3 关系模型

- **M:N 关系实体化**：`PLMLINK` 行表（`LID/PEID/PTYPE/CEID/CTYPE/LSEQUENCE/LQUALITY/…`），
  `<LinkedTypes ParentType ChildType ParentPrimaryKey ChildPrimaryKey>` 声明合法端点，
  `IsContainSub`（级联）、`LoopCheck`（防环）、`SequenceIncrement`（序号步长）。
- **1:N 外键**：普通字段 + `<ForeignKeyInfoList>`。
- **主从副表**：`IsGenerateViceTable=true` → `XXX$` 副表，`AsContainSub="SubAllRemoveSelf"` 控制级联删除。

### 3.4 三套状态机制（旧系统最大的复杂度来源）

| 机制 | 根属性 | 承载字段 | 说明 |
|---|---|---|---|
| 生命周期 | `PolicyName` | `STATEID` | 主状态机，`.life` 定义；`InforCenterState` = New/WorkFlow/PreRelease/Release/Stop/Abandon/Accept/Reject/Solve/Finish |
| 阶段（Phase/Gate） | `StagePolicyName` | `STAGESTATEID` | 如 `ApplyStageCircle` = Apply→Accept/Reject→Implement→Close |
| 工作流 | `IsAllowStartWorkfolw` | `WORKFLOWSTATE`(New/RUN/COMPLETE/STOP/SUSPEND/CANCEL) + `RELEASEDATE` | 审批流运行态，与上面两者解耦 |

`.life` 的 `State` 带 `ExtendProperty {"AllFlow":true|false}`：该状态是否允许发起任意流程。

### 3.5 版本机制

- 存整型 `DBValue`，显示按 `Custom.version` 映射：大版本 Letter（1→A，27→AA，Excel 列式），小版本 Number（1→001），分隔符 `.`（或 `-`）。
- 族标识：`EUID`（同族共享）+ `ELASTINSERT`（最新版标记）+ `ELASTFINALSTATE`；迭代 `CURITERATION`。
- **已知缺陷**：`Custom.version:38-55` 有 22 个 `DBValue="34"` 重复映射，字母版本超过 `AG` 后失效。

### 3.6 权限体系（五层，复杂度最高）

```
用户 ∈ 组；组 ⟷ 角色（GROUPROLE）；
① 功能点权限 MODULEPERMISSION（模块/菜单/按钮）
② 对象类型权限（ActionChecker ActionType=对象类型）
③ 对象实例权限 OBJECTPERMISSION（Actor=User/Role/Group/GroupRole/Creator/Owner/OwnGroup/AllUser，Action 位集合，可设到期时间）
④ 规则权限 ACTIONRULE + ACTIONRULECONDITION（扁平 AND/OR 条件树：属主/编码/名称/类型/已有权限/属性值/状态/阶段/父对象属性…）+ ACTIONRULEPERMISSION
⑤ 数据隔离：ECOMPANYID（集团）+ GROUPISOLATEINFO（组隔离映射）+ GROUPSHAREMAPPING（组共享视图）
审计：AUTHORIZEPERMISSIONLOG；操作日志 OPERATELOG（按月分区）
```

### 3.7 工作流引擎

模型族：`WORKFLOWTEMPLATE`（设计态，版本化）/`WORKFLOWINFO`（实例）/`WORKFLOWTASKINFO`（任务）/
`WORKFLOWACTORINFO`（执行人）/`WORKFLOWATTACHINFO`（业务附件）。

机制关键点：
- 执行人选择器可插拔（Group/Role/User/GroupRole/Creator/Admin，`.flowactor`）；
- 条件分支可插拔（流程参数 / 主对象字段值，`.flowcondition`）；
- 业务插件（`BusinessPlugin`）：`ChangeState`/`ChangeStageState` **是"流程驱动生命周期"的钥匙**；
- 会签（同节点多任务）、加签（`ASSISTTASKID`）、驳回（**用中文词表判定**：退回/驳回/拒绝/否决/不同意…）、
  委托（`AGENTUSERID` + 生效区间）、超时催办（`PLANNEDENDDATE` + `TIMEREXECUTERECORD`）、挂起/停止/恢复、撤回；
- 异步化：附件改状态、清授权、返签均入队列。

### 3.8 文件与电子仓

- `DocumentVault.Vault`：一个 Vault = 多物理节点，客户端按**自身 IP 落入 Range** 选最近节点（`Port 8887` 原生、`WsPort 8817` WebSocket）。
- `DOCFILEMODEL` 字段：`FILEPATH`（仓内相对路径）/`CURVOLUMEID`（卷）/`ITERATION`/`ISMAINFILE`/`CHECKOUT*`。
- 检入检出：`CHECKOUTSTATE=1/0` + `CHECKOUTUSER` + 软锁；检入生成新迭代；检入时强制刷新 `SHAREGROUPCODE`。
- 格式转换 = `CommandServiceManagement`（`CONVERSIONCOMMAND/CONVERSIONENDPOINT/COMMANDCLUSTER`），
  加密签名下发到 CAD 工作站；浏览器侧有 WebSocket 直连本机 ICP Viewer 的方案。

### 3.9 编码器

`CODEKIND`（大类，受生命周期 `CodeKindLife` + 权限管控）→ `CODERULE`（段：`THICKRULE` 粗规则=数字/字母/字母数字/日期/流水号，
`THINRULE` 细规则=字符集/日期格式，`Describe` 即生成用的 pattern）→ `CODERES`（流水库，`STATEID` 区分
`Initial`（预占）/`Applied`/`Occupation`/`Excuted`/`LoseEfficacy`）。
取号 SQL 在 `.cmdsql` 中**把状态名字面量写死**（`STATEID <> 'Initial'`），迁移时不可改名。

## 6. 缺陷与风险清单（重构时要主动修正的）

| # | 问题 | 影响 | 新系统对策 |
|---|---|---|---|
| D1 | 数千 XML 配置无版本/无校验/无灰度 | 改配置=改生产，易错难回滚 | 元数据入库 + 版本 + JSON Schema 校验 + 灰度发布 + 审计 |
| D2 | 反射式 `JSMethod/WebMethod` 字符串调用 | 编译期不报错，运行时才炸 | 动作注册表 + 强类型 Handler + 契约测试 |
| D3 | 状态名字面量写进 SQL | 改名即崩 | 枚举码表 + 常量类 + SQL 只用常量参数 |
| D4 | 三轨状态（STATEID/STAGESTATEID/WORKFLOWSTATE）语义交叠 | 状态不一致、难以排查 | 三状态明确职责 + 单一写入口（领域事件）+ 状态迁移表 |
| D5 | 大对象宽表 + 派生副表 `XXX$` | 表结构臃肿、扩展需改表 | 核心表 + JSONB 扩展属性 + 按需投影视图 |
| D6 | 文件仓按客户端 IP 选节点 | 网络变更即失效 | 对象存储 + 预签名 URL + CDN/反代，服务端寻址 |
| D7 | 密码/密钥明文写进 `.setting` | 严重安全风险 | 外部化配置 + Vault/加密 + 启动校验 |
| D8 | 版本号字母进位表损坏（>AG） | 版本号错乱 | 重写版本格式化器 + 单元测试覆盖到 AZ/BA |
| D9 | 单文件菜单 210KB、单模型 39KB | 合并冲突、改动风险集中 | 元数据拆分存储 + 按资源粒度版本化 |
| D10 | 无统一可观测性（仅日志文件） | 生产问题定位慢 | TraceId + Micrometer + OTel + 指标/告警 |
| D11 | 无 OpenAPI 契约，前后端靠页面绑定 | 无法对接第三方/移动端 | API First（OpenAPI 3）+ SDK 生成 |
| D12 | 权限规则为扁平 AND/OR，无嵌套 | 复杂场景表达不足 | 条件树（AND/OR/NOT 嵌套）+ SpEL/JSON Logic |
| D13 | 检索依赖 DB LIKE | 大数据量性能差 | PG 全文/ES + 索引设计 |
| D14 | 无自动化测试与迁移脚本版本管理 | 升级不可控 | Flyway + Testcontainers + E2E |

## 7. 复刻边界建议

**必须复刻（核心业务价值）**：元模型 + 权限 + 工作流/生命周期 + 文件仓 + 图文档 + 零部件/BOM +
变更 + 工艺（路线/工序/卡片/资源/工时）+ 项目任务 + 报表看板 + ERP 集成。

**改造替代（不做等价实现）**：
- 自研 WebForms 控件树 → Vue3 组件 + 元数据驱动表单渲染；
- 自研工作流 → Flowable 7（BPMN 2.0），保留原有执行人/条件插件语义；
- 自研电子仓/分布式文件服务 → MinIO（S3 兼容）+ 内容寻址；
- AutoVue/ActiveX 图档浏览 → 服务端转换（PDF/PNG/glTF）+ 浏览器查看器（可插拔，商业 SDK 作为可选集成）；
- Stimulsoft 报表 → 前端 ECharts + 服务端 EasyExcel/PDF（JasperReports 可选）；
- C++ CAD 命令服务 → 保留为外部"转换代理"，通过消息队列对接（不强求用 Java 重写 CAD 转换内核）。

**暂不复刻（按需）**：移动端 Native（先做响应式 H5）、三员分立的硬件介质登录（UKey/CA，保留接口）、
多语言全量（先中英）、老客户端 OCX 能力。
