## 二、本次发现并修复的缺口

### 1. 详情接口可用 id 越过数据作用域（高危）

- **现象**：列表接口（`DocService.page` / `ItemService.page`）调用了 `ScopeApplier.apply(...)` 做数据作用域过滤，
  但 `GET /api/v1/docs/{id}`、`GET /api/v1/items/{id}` 走的是 `objectMapper.selectById(id)`，
  **只校验了 objectType，没有校验作用域**——列表里看不到的别家公司数据，拼一个 id 就能读到完整详情。
- **修复**：`ScopeApplier.isVisible(companyId, orgId, ownerId)` 提供与查询侧**同一套语义**的单对象判定
  （`ALL` 放行 / `COMPANY` 比公司 / `ORG` 比组织集合 / `SELF` 比属主），
  在 `DocService.requireObject`、`ItemService.requireItem` 返回前调用；越权时统一抛"不存在"，
  不泄露对象是否存在（`ScopeApplier.java:56`、`DocService.java:461`、`ItemService.java:239`）。
- **注意**：`SYS_ADMIN` 的作用域是 `ALL`（集团管理员要看全集团），所以**验证隔离必须用 COMPANY 作用域的普通用户**，
  用 admin 测会误判成"没有隔离"。

### 2. 下载文件名可穿越目录 / 超长撑爆响应头（中危）

- **现象**：`GET /files/{id}/content?name=` 把用户传入的 `name` 原样（仅 URL 编码）写进 `Content-Disposition`。
  URL 编码能挡住 CRLF 注入，但 `../../etc/passwd` 解码后仍是路径、500 字符的文件名会撑大响应头。
- **修复**：`FileController.safeFileName` 只取最后一段（`\` 归一为 `/` 后截断）、去除控制字符、限长 200
  （超长保留扩展名），净化后为空则回退按 sha256 生成的名字（`FileController.java:157`、`:349`）。

### 3. 回归用例（SecurityHardeningTest）

一条用例串起 7 组断言，任一退化即红：

1. 未登录访问受保护接口 → 401；
2. 篡改令牌 → 401；
3. 已登录但无任何角色 → 对文档/看板/看板维护/建用户全部 403；
4. 跨公司隔离：COMPANY 作用域用户列表看不到别家公司文档、按 id 取 → 404；同时反向确认 admin（ALL）看得到，证明不是数据没插进去；
5. SQL 注入：`keyword=' OR 1=1--` 与 `%' OR '1'='1` 均返回 0 条（参数化生效，不是把全表放大）；
6. XSS：名称存 `<script>alert(1)</script>` 后接口原样返回、响应 `Content-Type` 为 JSON（前端 Vue 插值转义，服务端不做二次解释）；
7. 下载名：`../../etc/passwd` 只留 `passwd`、500 字符名截到 200、纯控制字符名回退 `file-<sha>`。

## 三、逐项自查表

| 控制项 | 现状 | 证据 |
|---|---|---|
| 用户身份鉴别 | 用户名+密码（BCrypt），access/refresh 双令牌，支持企业 SSO | `LoginService`、`SsoService` |
| 登录失败处理 | `sys_user.lock_until` 字段与失败计数，连续失败锁定 | `sys_user` DDL / `LoginService` |
| 首次登录改密 | `must_change_pwd` 标记，改密前限制业务接口 | `sys_user`、`AuthController` |
| 密码强度 | 8~64 位 + 至少 3 类字符 + 不得等于用户名；历史 3 条不可重用；有效期可配（默认不过期）；支持自助改密 | `PasswordPolicy`、`AuthService.changePassword`、`V76` |
| 功能权限 | 每个写接口 `@PreAuthorize` + 权限点；权限按角色授予 | 各 `*Controller`、`sys_permission`/`sys_role_permission` |
| 数据作用域 | `ALL/COMPANY/ORG/SELF` 四档，查询侧 `ScopeApplier.apply`、直取侧 `isVisible` | `ScopeApplier`、`DataScopeContext` |
| 跨公司隔离 | 列表与详情均已校验（本次修复详情） | 同上 |
| 审计 | `@Audit` 记录关键写操作（建/改/删/审批/下载/导出） | `common/audit`、`sys_audit_log` |
| SQL 注入 | 全部查询使用参数绑定（`{0}` / `?`），无字符串拼接用户输入 | 各 `*Service`、`SecurityHardeningTest` |
| XSS | 服务端不渲染 HTML；响应统一 JSON；前端 Vue 默认转义 | `Result`、前端模板 |
| 文件上传 | 大小上限 4GB；**已加扩展名闸门**（`nexplm.file.upload.blocked-ext`，默认挡 exe/jsp/html/svg 等，单文件与分片会话两个入口都校验）；**MIME/魔数校验与真实杀毒仍待整改**（扫描钩子默认 noop） | `FileService.ensureUploadAllowed`、`MultipartUploadService.create`、`application.yml` |
| 文件下载 | 需 `file.download` 权限 + 审计；文件名净化 | `FileController` |
| 凭据存储 | API Key 只存哈希并可轮换；通知通道 webhook/secret 只写不读 | `OpenApiService`、`NotifyService` |
| 传输加密 | 应用不强制 HTTPS，依赖前置 nginx 终止 TLS（部署要求，待确认） | `deploy/nginx` |
| 依赖漏洞 | **未接入 SCA（OWASP dependency-check / trivy），待整改** | — |
| 日志脱敏 | 登录与重置密码请求体不落审计参数（`recordArgs = false`）；DB 连接串在 `.env` 不入库 | `UserAdminController`、`.gitignore` |
