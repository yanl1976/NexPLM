# 六、旧系统数据迁移方案

> 目标：把 InforCenter PLM（MSSQL/Oracle 等）中的主数据、结构数据、文档元数据与文件实物，
> 迁移到 NexPLM（PostgreSQL + MinIO），过程可校验、可增量、可回滚。

## 1. 迁移原则

1. **只迁数据，不迁结构**：旧表结构不复刻；按语义映射到新模型。
2. **保留追溯**：每条新记录在 `ext_json.legacy = {"table":"DOCMASTER","id":"..."}` 中保留旧主键，便于对账。
3. **先主数据后业务数据**：组织/用户 → 字典/编码 → 物料/零部件 → 文档与文件 → BOM → 工艺 → 项目任务 → 变更/质量。
4. **可重跑**：迁移程序幂等（按 `legacy.id` upsert），支持全量与增量（按 `UPDATETIME` 水位）。
5. **不动源库**：只读连接，禁用任何写操作；迁移窗口内源系统可继续运行（增量追赶）。

## 2. 迁移工具形态

独立 Java 模块 `plm-migrator`（Spring Boot CLI，非 Web）：

```
plm-migrator/
  source/    旧库只读访问（JdbcTemplate + 方言）
  reader/    分页读取器（键集分页，批 1000）
  transform/ 语义转换器（每个域一个 Transformer）
  writer/    批量写入（JDBC batch upsert）
  verify/    校验器（条数、抽查、哈希）
  report/    差异报告（HTML + CSV）
```

执行：`java -jar plm-migrator.jar --domain=doc --mode=full|incr --dry-run=true|false --batch=1000`

## 3. 域映射与关键转换

| 域 | 旧表 | 新表 | 转换要点 |
|---|---|---|---|
| 组织 | `COMPANY/ORGANIZATION/GROUPINFO/PERSON/USERINFO/ROLEINFO/GROUPROLE` | `sys_company/sys_org/sys_group/sys_user/sys_role/sys_group_role` | 组织树按 `PEID` 递归建 `path`；用户密码不可迁移（BCrypt/自定义哈希）→ 首次登录强制重置；`SECURITYLEVEL`→`security_level` |
| 枚举/字典 | `ENUMERATION/ENUMERATIONITEM` + `*.dic` | `meta_enum/meta_enum_item` | 旧 `.dic` 的中文标签导入为 `name` |
| 编码 | `CODEKIND/CODERULE/CODERES/CODEVALUE` | `code_rule/code_sequence/code_history` | `THICKRULE/THINRULE` → `segments_json`；`CODERES.ORDINAL` 作为 `current_no` 起点；**保留 `Initial` 预占语义** |
| 零部件 | `PSEITEM/PSEITEMMASTER/PSEBASEFORM(+子表单)` | `plm_object(type=PseItem)` + `pse_item` | `ITEMTYPE`→`pse_item.item_type`；`EVERSION/EMINORVERSION`→`revision/iteration`；`EUID`→`master_id` 映射表 |
| BOM | `PSEBOMLINE` | `pse_bom_line` | `PEID/CEID`→`parent_id/child_id`；`LQUALITY`→`qty`；`PVIEWTYPE`→`view_type`；`LVALIDITYID`→有效性区间 |
| 图文档 | `DOCMASTER/DOCDATASET/DOCFILEMODEL` | `plm_object(type=PdmDoc)` + `doc_master` + `file_object/file_link` | 文件按 `FILEPATH + CURVOLUMEID` 从 Vault 取出 → sha256 → MinIO；`CHECKOUT*`→`plm_checkout`；多文件→多条 `file_link` |
| 分类 | `CLASSIFYCLASS/CLASSIFYATTRIBUTE/CLASSIFYRELATION` | `class_node/class_attribute` | 分类属性继承关系保留 |
| 工作空间 | `WSFOLDER/WSFOLDERCONTENT` | `ws_folder/ws_folder_content` | `POSITION`/目录字段→`ws_folder_content` |
| 变更 | `CMAPPLY/CMNOTICE/CMPROBLEM/CMRELATION` | `cm_change/cm_change_relation` | 三类单据统一为 `cm_change.change_kind`；阶段状态映射到 `phase_state` |
| 工艺 | `PROUTE/MSESTEP/MSEPROCESS/CREPORTOBJECT/TIMEQUOTAMASTER/CAPPRESOURCE*` | `capp_route/capp_operation/capp_process/capp_report/capp_time_quota/capp_resource` | 工序序号重排；卡片内容 `content_json` 先原样迁移（结构化在 P6 增强） |
| 项目/任务 | `PROJECT/PMTASK/PROJECTPLAN*/PROJECTFOLDER*` | `prj_project/prj_task/prj_task_output` | WBS 层级→`parent_id + wbs_code`；计划/实际日期转换 |
| 质量 | `QPROBLEM/QPROBLEMSOLUTION` | `qm_problem/qm_problem_action` | 多轮整改→`round` |
| 权限 | `OBJECTPERMISSION/ACTIONRULE*` | `sys_acl_entry/sys_permission_rule` | 条件平铺 AND/OR → 转成两层树（保持语义）；Actor 类型映射 |
| 流程 | `WORKFLOWINFO/WORKFLOWTASKINFO`（历史） | 只迁**归档快照**到 `sys_audit_log`/只读表 `his_workflow` | 运行中流程不迁移（切换窗口内结束或作废），避免双引擎并存 |

## 4. 文件迁移（重点与难点）

1. **盘点**：从 `DOCFILEMODEL` 导出清单（对象 ID、卷、相对路径、大小、扩展名）。
2. **读取**：按卷配置（`DocumentVault.Vault`）挂载或通过旧文件服务 API 读取；批量拉取到临时区。
3. **计算指纹**：`sha256`；与清单中的大小比对，不一致入"可疑清单"。
4. **入库**：按 `sha256[0:2]/[2:4]` 分目录写入 MinIO；已存在则跳过（去重）。
5. **建链**：`file_object`（唯一 sha256）+ `file_link`（owner=新对象 ID，role=MAIN/ATTACHMENT，version）。
6. **校验**：抽样 5%（不少于 500 个）下载回来比对 sha256；全量比对清单条数与总大小。
7. **失败处理**：文件缺失 → 记录到 `migration_issue`，对象标记 `ext_json.missingFile=true`，业务可后补。

吞吐目标：≥ 50 MB/s；断点续传（每批记录 checkpoint）。

## 5. 迁移步骤（一次完整切换）

| 步 | 动作 | 校验 |
|---|---|---|
| 1 | 环境准备：新库、MinIO、迁移账号（源库只读） | 连通性、权限 |
| 2 | 全量迁移主数据（组织/用户/角色/字典/编码） | 条数一致；抽样 100 条字段比对 |
| 3 | 全量迁移对象与结构（零部件/BOM/文档元数据/工艺/项目） | 条数一致；BOM 展开抽样比对 20 棵树 |
| 4 | 文件迁移（可并行多进程） | sha256 抽样；总数/总大小 |
| 5 | 迁移权限与规则 | 抽样 30 条 ACL 生效验证 |
| 6 | 全量校验 + 差异报告 | 差异率 < 0.1%（可接受项需人工确认） |
| 7 | 业务验证（关键用户 UAT，1 周） | UAT 用例通过率 100% |
| 8 | 切换：源系统只读 → 增量追赶 → 停写 → 最终增量 → 开放新系统 | 增量差异为 0 |
| 9 | 回滚预案：保留源系统 30 天只读；新系统问题可回退 | 演练已通过 |

## 6. 校验指标（自动生成报告）

- 记录级：每域 `源条数 / 成功 / 跳过 / 失败`，失败明细 CSV；
- 字段级：每域随机 200 条，逐字段比对（忽略类型转换差异），输出差异率；
- 结构级：BOM 树深度/节点数/总用量比对；文档版本链长度比对；
- 文件级：条数、总大小、sha256 抽样一致率；
- 权限级：抽样用户的"可见对象集合"新旧比对（Jaccard 相似度 ≥ 0.99）。

## 7. 特殊注意

1. **旧 ID 保留**：新库用雪花 ID，但 `ext_json.legacyId` 必存，保证外部系统（ERP/报表）对账。
2. **状态映射表**：`New/WorkFlow/PreRelease/Release/Stop/Abandon` → 新生命周期状态，需业务确认一次（写死在 `StatusMapping` 常量并单测）。
3. **密级/共享组**：旧 `OWNGROUPCODE/SHAREGROUPCODE` 语义模糊，迁移时先映射为 `security_level` + `ACL(READ)`，并在报告中标出需人工复核的记录。
4. **时间**：旧 `LONG` 毫秒时间戳按服务器时区（默认 Asia/Shanghai）转 `timestamptz`；时区不一致的记录单独标记。
5. **重复编码**：旧系统允许跨组织同编码，新库唯一约束按 `object_type + company_id`，冲突清单需业务裁决。
6. **不迁运行中流程**：切换前一周冻结新流程发起，存量流程在新系统"历史流程"只读展示。

## 8. 增量与双跑

- 增量水位：`UPDATETIME`（毫秒）+ 主键；每 5 分钟跑一次，记录 `watermark`。
- 双跑期：新系统只读并行（用迁移数据演示），不做双写（避免一致性灾难）。
- 切换窗口：≤ 4 小时（增量追赶 + 最终校验 + DNS/入口切换）。
