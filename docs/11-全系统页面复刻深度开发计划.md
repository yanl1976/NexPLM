# 全系统页面复刻深度开发计划

> 目的：把旧系统 PLMSOFT（华天 InforCenter Platform 9.4）的**页面、功能、菜单、程序集**盘清，逐域对照 NexPLM 现状，排出可执行的分批开发计划。
> 证据规则同 `06-探查记录.md`：本文只放结论与清单，探查过程与「怎么查到的」见 `EXP-20261107-12`；单模块的逐页字段级证据在该批次执行时另出深度探查报告（先例：`10-深度探查-零部件管理.md`）。
> 盘点日期：2026-11-07。

## 0. 一页结论

| 维度 | 旧系统（PLMSOFT） | 新系统（NexPLM） | 差距性质 |
|---|---|---|---|
| 一级菜单域 | **19 个**（含 4 扩展域、1 隐藏），**113 个可见菜单项** + 1 隐藏 | 侧边栏 **11 组**、44 个桌面路由 + 3 移动端 | 缺 8 类入口，多数是「个人/工具/配置」型 |
| 页面定义 | `.page` ≥1,850、`.listview` 234、`.menu` 319、`.link` 175、`.nav` 86、`.dic` ≈3,200、`.view` ≈700 | 51 个 `.vue`（桌面 47 + 移动 3 + 登录 1） | 旧是「配置生成」，新是「手写页面」，**不能 1:1 对齐页数**，只能按业务功能对齐 |
| 后端 | 239（`Server/Bin`，含 44 个 WCF WebService）+ 272（`InforCenter/*`）+ 141（`Platform/Bin`） | 54 个 `@RestController`，V1~V54 迁移 | 能力面已覆盖主干，缺「工具类/配置类」能力 |
| 客制 | **TSDC 14 个程序集** + 5 个 WCF 服务 + 7 个 `.plugin/.flowplugin` + JS 注入 | 部分内化（金蝶适配器、物料对象扩展） | 客制点需逐条确认「内化 / 放弃 / 待定」 |
| 集成 | 金蝶云星空 **5 条下发链路** + `ERPConfig.xml` 三段字段映射 + 5 个 JSON 模板 | P9-1~P9-6 框架齐备，`KingdeePayloadService` 支持 4 条 | 缺「请购单」链路与「字段映射可视化」，且未真机联调 |

**结论**：主干（文档/零部件/变更/工艺/项目/质量/供应商/集成/看板）已成型，剩余工作集中在三类——
① **个人工作区与全局工具**（我的检出/收藏/最近访问/高级查询/内部邮件）；
② **配置与主数据运营**（编码管理、工厂结构/工位/消耗、材料定额、工装、值列表运营）；
③ **报表与外部协同**（报表管理、数据协同、ERP 五链路真机联调）。

### 3.2 扩展点（复刻时要对齐的机制）

1. **App 注册**：`Server/Config/Apps.app:247-274` 定义 `<Apps Name="TSDC" Context="TSDCContext">` —— 客制生效总开关。
2. **`.plugin`**（业务/对象/值类型扩展）：`PluginItem Name Type Assembly Class`，Type 有 `ObjectType / Business / ObjectValueType / Message / EAIMessage / LifeCycleExtend`。客制例：`TSDC/PSE/Item/Config/Plugin/PSEItemplugin.plugin:3`。
3. **`.flowplugin`**（工作流节点插件）：`UseByType = AuditNode | BusinessNode | Workflow` —— **ERP 五条下发链路都在这里**（`TSDC/ERP/Config/Plugin/SendErp.flowplugin:3-13`）。
4. **`.service`**（WCF/RPC 契约）、**`.fileref`**（前端 JS 注入）、**`.cmdsql`**（SQL 模板）、**`.setting`**（键值配置）。

> 新系统对应物：`WfBusinessPlugin`（≈`.flowplugin`）、`NotifySender/NotifyPublisher`（≈`Message`）、`MetaController`（≈`ObjectType/ObjectValueType`）、`AclService/SecurityRule`（≈`ModulePermission`）。**机制已具备，缺的是具体客制项逐条内化。**

## 6. 分批开发计划

排序原则：**先补高频入口（人每天要用）→ 再补主数据运营 → 再补报表与外部协同 → 最后处理客制与真机联调**。每批独立可验收、独立提交。

### 批次 A｜个人工作区收口（P0，2~3 天）✅ 已落地（2026-11-07）

> 落点：后端 `V55__my_workspace.sql`（`plm_favorite` / `plm_access_record` / `sys_notify_message.read_at`）+ `MyWorkController`（`/api/v1/my/*` 11 个端点）；前端 `/my/{checkouts,favorites,recent,search,messages}` 五路由共用一个 `MyWorkView.vue`（靠 `props.tab` 切换），侧边栏新增「个人工作区」组。
> 与旧系统的口径差异：旧系统 `FAVORITELINK` 是树形（父级 `PEID` + `LSEQUENCE`），本批先收敛成「单层分组 + seq_no」；旧系统收藏夹含文件夹节点，这里只收藏对象。

| 页面/能力 | 旧系统对应 | 新系统落点 | 验收口径 |
|---|---|---|---|
| 我的检出 | `MyCheckOut`（`VerticalTabManagement`） | `/my/checkouts`：跨文档/零部件列出我持有的检出锁，支持撤销检出 | 列表含对象类型/编码/名称/检出时间；撤销后锁释放、对象可被他人编辑 |
| 收藏夹 | `Favorite`（`FavoriteManagement` 树） | `/my/favorites`：文档/零部件/项目多类型收藏，可分组 | 收藏/取消、按类型筛选、点击跳详情 |
| 最近访问 | `AccessRecord`（`AccessRecordManagement`） | `/my/recent`：按时间倒序，保留 30 天 | 访问详情自动记一条；按类型过滤 |
| 高级查询 | `QueryMachine` / `AdvancedQuery` | `/search`：跨对象类型（文档/零部件/变更/项目）组合条件查询 + 保存查询方案 | 条件可保存复用、结果可下钻、分页稳定 |
