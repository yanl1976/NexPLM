# 十二、PLM 复刻方法论（蓝本取证 → 判等交付）

> 定位：本文是**复刻类工作的执行规程**，回答"每做一个功能，先做什么、后做什么、做到什么程度算完、没做完怎么记"。
> 与既有文档的关系：`04-工程规范与质量门禁.md` 管**通用工程标准**（分层、命名、测试、API、安全）；本文管**复刻特有动作**（蓝本取证、业务关联分析、差异决策、判等验收、留口登记）。两者同时生效，冲突时以更严者为准。
> 强制级别：本文所有"必须"为硬约束。违反任一条的产出视为**未完成**，不得计入进度、不得提交为 `feat`。

---

## 0. 为什么要有这套规程

历史问题不是"做得慢"，而是**做事顺序不固定**，导致同一类事情重复返工：

| 症状 | 真实案例 | 根因 |
|---|---|---|
| 按名字当需求做 | `EXP-20261107-20`：批次 H 五项里只有 CIS 与零部件分类在蓝本里启用了，多维表/需求会议两套二开包整行被注释 | 没查**启用开关**（`Apps.app`）就开始评估工作量 |
| 记录当真、未复核 | `docs/03` B5：旧表写"后端已具备"，实际三项批量接口根本不存在，只能当场补齐 | 结论没有落到**证据**（路径:行号），转述即失真 |
| 改一处塌一片 | `EXP-20261107-21`：`ext_json` 原本"每次重建"，照原样加字段会导致一次编辑抹掉全部客制字段 | 只看了字段名，没读**写入语义** |
| 接口通了当功能完成 | `EXP-20261107-21` 结尾：接口已可写可读，但用户侧"看不见、改不了"，差点按已完成交付 | 验收口径停在"后端有没有"，没到"用户能不能用" |
| 口径分裂 | `docs/03` B1：预览转换器与引擎判定双实现共存；出库明细曾有 4 套实现（后续收敛为 `outstock-detail-handler` 单一数据源） | 新做功能时不查"这件事以前有没有人做过" |

**结论**：复刻不是"照页面画一遍"，而是**先建立蓝本的事实底座，再决定复刻到什么程度，最后用可验证的判等标准收口**。

## 1. 适用范围与术语

- **蓝本**：`PLMSOFT/`（华天 InforCenter Platform 9.4）+ 客制程序集（`TSDC/`）+ 现场数据。
- **复刻**：使新系统在**业务结果**上与蓝本等价（不要求实现方式相同）。
- **判等**：在字段、校验、交互、权限、数据、报表六个维度给出"与蓝本一致"的可核对结论。
- **留口（GAP）**：明知与蓝本不一致、但本轮不做的地方。必须显式标注、可统计，**禁止用假数据让它看起来一致**。
- **取证**：把"蓝本是怎么做的"变成可复查的事实（文件、行号、SQL 结果、运行截图、字符串证据）。
- **证据等级**：`E0` 界面可见 → `E1` 配置可读（`.page/.model/.setting/.enum`）→ `E2` 程序可读（DLL 字符串、SQL、插件）→ `E3` 运行可验（真机、库内数据）。
- **结论等级**：`已证实`（有 E2/E3 证据或 E1 明确声明） / `高置信推断`（多个 E1 互证） / `待验证`（只有 E0 或类比）。**`待验证` 不得写进"已验证事实"**。

## 2. 五条铁律

| 编号 | 铁律 | 落地判据 |
|---|---|---|
| **R1** | **无取证不开工**（No Evidence, No Code） | 任务卡里"蓝本行为"一栏每一条都带 `路径:行号` 或 SQL 结果；没有就先去查，不写代码 |
| **R2** | **单一事实源** | 同一业务口径只允许一个实现（一个 handler / 一张表 / 一个字段）；发现第二套必须收敛或登记为遗留 |
| **R3** | **判等交付** | 交付以第 8 节 DoD 清单为准，六维逐项勾选并附证据；"接口返回 200"不算完成 |
| **R4** | **留口显式化** | 与蓝本不一致处必须 `GAP(T-xx-nn)` 标注 + 台账登记；**禁止 mock 冒充真实数据**、禁止静默降级 |
| **R5** | **一次一件事** | 开工先冻结范围（做什么/不做什么）；收口按章节提交；**禁止顺手改**无关文件 |

## 3. 角色（单人开发也要"换帽子"）

| 帽子 | 职责 | 产出物 | 常见失职 |
|---|---|---|---|
| 任务负责人 | 定范围、排先后、判"停/做/延" | 任务卡（附录 A） | 范围不清，边做边加需求 |
| 取证员 | 只读蓝本，产出事实与证据 | 探查记录 `EXP-*`（附录 B） | 只截界面，不看配置与程序 |
| 实现者 | 迁移/后端/前端，严守 R2/R5 | 迁移脚本、接口、页面 | 顺手重构、复制第二套口径 |
| 验收员 | 按 DoD 判等，只认证据 | 验收单（附录 D） | 用开发者自己的描述验收 |
| 业务确认方 | 回答口径与取舍问题 | 台账 D 类答复 | 问题没编号，答复无记录 |

> 单人时**同一人不得用"实现者"身份自验收**：验收必须重跑一次蓝本对照（第 6 节 V4/V5），以证据代替记忆。

## 4. 复刻流水线（R0~R8，逐道门禁）

**顺序总则（"依次复刻"的确切含义）**：

1. 批次顺序以 `docs/11` 的 A→H 为准；**同一时刻只允许一个批次在"实现阶段"**（可以并行取证，不允许并行铺代码）；
2. 批次内按「被依赖者优先」排序（主数据 → 单据 → 报表/集成），同层则「阻塞最少者优先」（业务答复齐的先做）；
3. 一个任务走完 R0~R8 才开下一个；被 D 类问题卡住时，转去做同批次内**不依赖该答复**的任务，并把当前任务卡状态置"待答复"，**不留半成品代码**；
4. 严禁跳批次抢"看起来快"的功能——跨批次并行会让同一张表被两个任务的迁移脚本争抢。

| 步骤 | 名称 | 输入 | 产出 | 门禁（不通过则退回） |
|---|---|---|---|---|
| **R0** | 任务立项 | `docs/11` 批次清单 | 任务卡 `T-<批次>-<NN>`（含"不做清单"） | 范围含"不做什么"；验收口径初稿可判等 |
| **R1** | 蓝本取证 | 任务卡 | `EXP-*` 记录（界面/配置/程序/数据四类证据） | 每条蓝本行为都有证据+等级；无 `待验证` 混入事实 |
| **R2** | 业务关联分析 | `EXP-*` | "上下游一页纸"（第 7 节模板） | 上游输入、下游影响、共用口径、状态机、权限、异常路径齐全 |
| **R3** | 差异判定与决策 | R1+R2 | 处置表（复刻/替代/不做/延后）+ ADR（如需） | 每处差异四选一；"替代/不做"必须写影响与补偿 |
| **R4** | 设计 | 处置表 | 数据模型变更、API 契约、前端信息架构、口径定义 | 复用优先已核对（R2 的"共用口径"）；不新增第二套口径 |
| **R5** | 实现 | 设计 | Flyway 迁移 + 后端 + 前端 | 迁移只增不改；状态写入单一入口；无 `SELECT *` |
| **R6** | 验证（V1~V5） | 实现 | 门禁结果 + 对照证据 | 五层全绿（见第 6 节），V4 数据判等须有抽样对照 |
| **R7** | 留口与记录 | R6 结果 | `EXP-*` 收口段 + GAP 标注 + 台账登记 | 遗留有编号、有归属、有解锁条件 |
| **R8** | 交付收口 | 全部产出 | 提交（引用 `T-*`/`EXP-*`）+ `docs/03` 进度与台账回填 | 进度表只写"已验证通过什么"，不复述过程 |

### R0 开工自检（10 问，答不全不许写代码）

1. 这次涉及蓝本哪些**页面/菜单**（`.page/.menu` 文件名与路径）？
2. 涉及哪些**后端入口**（WCF/Service/存储过程/插件 DLL）？
3. 涉及哪些**表与字段**（表名 + 关键列 + 数据量级）？
4. **启用状态**如何？（`Apps.app` 开关、`*.setting` 配置、是否有被注释）
5. **上游**谁产生这些数据？（单据/流程/导入/接口）
6. **下游**谁消费？（报表/打印/下发 ERP/其他模块展示）
7. 与现有哪个功能**口径重叠**？（有则指定唯一数据源）
8. 蓝本的**权限点与数据范围**是什么？（菜单权限、对象 ACL、组织隔离）
9. 蓝本的**异常与边界**行为？（空值、超量、重复、并发、撤销）
10. 本轮**明确不做什么**？（写进任务卡"不做清单"）

## 5. 取证规范（R1 怎么做才算够）

### 5.1 按资产类型取证

| 资产 | 位置 | 取证手段 | 证据粒度 | 常见坑 |
|---|---|---|---|---|
| 页面定义 | `PLMSOFT/**/Pages/*.page` | 读 XML/JSON：字段、列、按钮、事件、可见条件 | 文件:行号 + 字段清单 | 页面列 ≠ 实体字段（视图里可能是计算列） |
| 列表/视图 | `*.listview` / `*.view` | 列定义、默认排序、筛选方案 | 列名+来源字段 | 客制视图与标准视图并存，要确认现场用哪个 |
| 数据模型 | `*.model` / `*.schema` | 实体、字段、类型、长度、必填、关联 | 字段表 | `model` 里的字段可能不落库（虚拟字段） |
| 菜单与权限 | `*.menu` / `Apps.app` / 角色配置 | 菜单树、权限码、启用/注释状态 | 行号 + 启用判定 | **整行被注释 = 未启用**，不要按名字当需求 |
| 配置/开关 | `*.setting` / `*.config` / `*.xml` | 关键开关、路径、映射表 | 键值 + 默认值 | 同一键在多处配置，取值优先级不明时标 `待验证` |
| 枚举/字典 | `*.enum` / `*.dic` | 码值、默认值、是否可扩展 | 值清单 | 字典可运营（现场可能加值），不要硬编码 |
| 业务规则 | `Server/**/*.dll`、`TSDC/**/*.dll`、`.plugin` | 字符串取证（ASCII/UTF-16）、类名/方法名、SQL 片段、报错文案 | 类/方法/SQL + 证据方式 | 只能"读"不能"跑"；反编译结论一律 `高置信推断` |
| 存储过程/视图 | 现场库 `sysobjects`/`sys.sql_modules` | 取定义文本，读 WHERE/JOIN/口径 | 对象名 + 关键片段 | 库里可能有多版本同名对象 |
| 报表 | `QRNR_*` 报表对象、`*.rpt`、插件 DLL | 元数据 + 插件字符串 + 列清单 | 列清单 + 取数口径 | 报表 SQL 常编译进 DLL，只能靠字符串与运行结果反推 |
| 工作流 | `*.flow` / `*.flowplugin` / 流程配置 | 节点、分支条件、执行人解析、归档动作 | 节点表 + 条件 | 分支条件常写在插件里 |
| 打印模板 | `*.print` / 模板文件 | 版式块、取数变量 | 版式清单 | 打印口径与页面口径可能不同源 |

### 5.2 记录格式（附录 B）

一条探查记录 = 一条 `EXP-YYYYMMDD-NN`，五段固定：**目标问题 → 范围与方法 → 关键发现（带 `路径:行号`）→ 结论与决策 → 遗留与后续动作**。同日递增、只增不删；结论被推翻时**新开一条**，旧条目标"已被 EXP-xxx 推翻"。

### 5.3 二进制/DLL 红线

- 只允许**只读**取证：字符串提取、元数据表查询、运行现场功能观察；
- 不反编译后重编译、不注入、不改蓝本库；
- 任何来自 DLL 的结论默认 `高置信推断`，**必须真机验证后才可升为 `已证实`**，且升级动作要记进同一条 EXP 的补充段；
- 报错文案、SQL 片段、字段名是最有价值的证据，**原样引用**，不要改写。

## 6. 验证门禁（R6）

| 层 | 内容 | 通过标准 |
|---|---|---|
| **V1 静态** | 后端 `mvn -pl plm-app -am test-compile`；前端 `npx vue-tsc --noEmit` | 零编译错误、零新增告警 |
| **V2 单测/集成** | 领域规则、状态机、口径计算、迁移脚本 | 新增代码行覆盖 ≥70%；关键口径有断言 |
| **V3 接口契约** | 每个新接口的成功/失败/越权三态；分页与空态 | 三态均有用例；错误码符合 `04` 第 7 节 |
| **V4 数据判等** | 用蓝本同一业务对象（抽样 ≥20 条，含边界）比对两边结果 | 差异为 0，或每处差异有 `GAP` 编号与原因 |
| **V5 UI 走查** | 字段/列/按钮/页签/校验/默认值/空态/权限可见性逐项对照蓝本截图 | 逐项打勾；缺失项进台账 |

> **V4 是本方法论的核心**：没有"同一对象两边比对"的复刻，无法证明复刻成功。只做 V1~V3 的交付，状态最多记"代码完成，未判等"。
> 环境不具备（无测试账套/无现场数据）时，**必须**把该项登记为台账 A 类，并把任务状态写成"待判等"，不得写"已完成"。

## 7. 业务关联分析模板（R2，"上下游一页纸"）

```
T-<批次>-<NN> 上下游一页纸
1) 本功能在单据链的位置：[上游单据] → 【本功能】 → [下游单据/报表/下发]
2) 输入：谁写入（页面/接口/导入/流程），写哪张表哪个字段，唯一性约束是什么
3) 输出：谁消费（报表/打印/ERP 下发/其他模块），消费时按什么口径过滤
4) 共用口径：与哪些既有功能共享同一批数据；若已有实现，指定唯一数据源（R2）
5) 状态机：有哪些状态、谁能改、非法迁移怎么拒（旧系统的拒绝文案是什么）
6) 权限：菜单权限码、对象级 ACL、组织/数据范围；越权时蓝本的行为
7) 异常与边界：空/重/超量/并发/撤销/删除保护；蓝本的表现
8) 组织与时间：是否跨组织、是否按期间（年度/月度）切换口径
9) 与 ERP/外部接口：有无下发/回查，字段血缘到哪个 `F*` 列
10) 不做清单：本轮明确不覆盖的项 + 影响面
```

## 8. 判等验收清单（DoD）

一个功能只有在下列六维全部有结论（打勾或 `GAP` 编号）时才可交付：

| 维度 | 检查点 |
|---|---|
| 字段 | 页面显示字段/列、顺序、必填、默认值、长度与精度、字典显示名、计算列口径 |
| 校验 | 前端即时校验与后端强校验一致；错误文案可懂；拒绝不留脏数据 |
| 交互 | 按钮位置与可用条件、批量操作、上下移/拖拽、弹窗 vs 抽屉、双击下钻、快捷键（如有） |
| 权限 | 菜单可见性、按钮级权限、对象 ACL、组织隔离、越权返回"不存在"而非"无权限"（与蓝本一致时） |
| 数据 | 落库字段与蓝本同义、状态写入单一入口、审计与状态日志、删除保护、版本/修订语义 |
| 报表/输出 | 导出列与排序、打印版式、ERP 下发报文字段、合计口径与蓝本一致 |

附加（有则必查）：性能门禁（列表/展开/汇总 P95）、移动端、导入模板与逐行结果。

## 9. 留口（GAP）规范

- **三态处置**（R3 结论的唯一合法取值）：
  - `REPLICATED` 复刻：行为与蓝本等价；
  - `SUBSTITUTED` 替代：换实现但业务结果等价，必须写清"为什么等价 + 差异在哪"；
  - `DEFERRED` 延后/不做：写清影响面、临时补偿、解锁条件。
- 代码内标注格式（紧贴实现处，便于检索）：
  ```java
  // GAP(T-G-04): 旧系统 FErpClsID 支持中文名与编码双写，当前只写原值，等真机联调确认（EXP-20261107-21）
  ```
- **禁止**：用 mock/常量/`0.15 * 合同额` 之类的估算数字填充缺口；用 `try/catch` 静默吞掉失败当作成功；把"没配"显示成"已完成"。
- 缺口必须**可统计**：任务收口时给出"本任务 GAP 数与清单"，并进台账。

## 10. 遗留与待确认的管理

**唯一台账 = `03-分阶段实施计划.md` 的「未完成任务清单」**（禁止另建第二份清单，避免口径分裂）。四类：

| 类 | 含义 | 登记字段 |
|---|---|---|
| **A** | 阶段 DoD 未验收（代码就绪，缺环境/凭据） | 项 / 阻塞原因 / 解锁条件 |
| **B** | 功能实现遗留（能做但本轮没做/做得不完整） | 项 / 现状 / 归属批次 |
| **C** | 计划内未开工（`docs/11` 批次） | 批次 / 状态 |
| **D** | 待业务确认（口径、取舍、范围） | 问题编号（Q*）/ 问题 / 影响 / 答复期限 |

规则：

1. **任务内**：开工时先看台账有没有相关项；收口时新增/更新行，**同一行不重复登记**；
2. **升级**：任务内 TODO 超一个迭代未关闭 → 升级为 B 类；影响验收 → 升级为 A 类；
3. **关闭**：必须有证据（提交号或 EXP 编号）才可关闭，关闭时保留原行并标"已收口（日期/证据）"，不删除；
4. **盘点**：每周一次，只做两件事——把新发现的项归类、把已关闭的项标收口。

## 11. 追溯与提交

- **ID 体系**：任务 `T-<批次>-<NN>`（子片 `T-H-01a`）；取证 `EXP-YYYYMMDD-NN`；决策 `ADR-NNNN`；缺口 `GAP(T-xx-nn)`；遗留沿用台账编号（A/B/C/D + 序号）。
- **一个任务 = 一组提交**，按"迁移 → 服务/接口 → 前端 → 测试 → 文档"切片提交，不攒到最后；
- 提交信息中文，作用域用模块名，正文**引用任务与证据**：
  ```
  feat(pse): 详情页客制字段入口（T-G-01）

  取证：EXP-20261107-22；判等：字段/交互/权限三维通过，数据判等待真机联调（台账 A4）
  ```
- 提交前 `git status` 只应包含本任务的切片；发现无关改动**先问再做**，不顺手带。
- 禁止：提交密钥、`target/`、`node_modules/`、临时脚本（用完即删）。

## 12. 反模式清单（出现即返工）

1. **跳级开发**：没出 EXP 就写代码（R1 违规）。
2. **按名字当需求**：不查启用开关/配置，把被注释的模块当要做的功能。
3. **口径第二套**：同一统计另写一条 SQL/另一个 handler；发现重叠不收敛。
4. **假数据填坑**：用估算值/默认值让页面"看起来有数"。
5. **后端通关当功能完成**：接口 200 但用户侧无入口、无展示。
6. **只做正向**：不测空态、越权、重复、并发、撤销。
7. **顺手重构**：一个提交里混入无关改动，事后无法回滚单个意图。
8. **文字结论无证据**：`路径:行号` 缺失，转述即失真（见 `docs/03` B5 教训）。
9. **待验证混入事实**：把推断写进"已验证事实"，后续据此设计。
10. **遗留口头化**："下次一起弄"——没有编号、没有台账行，等于没记。

## 13. 节奏与产出物

一个任务的最小产出物清单（缺一即未收口）：

- [ ] 任务卡（含不做清单）
- [ ] `EXP-*`（至少 1 条，含证据与结论等级）
- [ ] 上下游一页纸（R2）
- [ ] 处置表（R3，四选一）+ ADR（如需）
- [ ] 迁移脚本（如需，只增不改）
- [ ] 后端 + 前端实现
- [ ] V1~V5 门禁结果（V4 附对照数据）
- [ ] GAP 清单 + 台账登记
- [ ] `docs/03` 进度回填（只写"验证通过什么"）
- [ ] 提交（引用 `T-*` / `EXP-*`）

建议节奏：**取证与设计占任务工时 30%~40%**，实现 40%，验证与文档 20%~30%。若实现时长明显超过取证时长，多半是跳了 R1/R2。
