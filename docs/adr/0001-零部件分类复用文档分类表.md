# ADR-0001 零部件分类复用文档分类表（doc_class + entity_code）

- 状态：已采纳（2026-11-08，业务/技术决策：用户选择方案 A）
- 关联：`T-H-01`（任务卡 `docs/tasks/T-H-01.md`）、取证 `EXP-20261108-01`、台账 `REP-H-01`、迁移 `V71__item_classify.sql`

## 背景

蓝本 `Classify`（维护）+ `ClassifyUse`（检索）需要复刻为「分类树 + 分类属性（必填/枚举/可继承）+ 按分类检索零件」。
取证结论（`EXP-20261108-01`）：蓝本用「5 类节点实体 + 通用链接表 `CLASSIFYLINK` + 属性 EAV」的元模型，新系统没有 `PLMLINK` 机制，不能 1:1 搬。

新系统 P2 已有一套成型的同类能力：`doc_class` / `doc_class_attr`（P2，V8），特点：

- 已按 `entity_code` 区分对象类型（默认 `PdmDoc`），唯一索引为 `(entity_code, code)`；
- `path` 为「/父编码/子编码」，子树检索按路径前缀，换父级/改编码时同步子树；
- 属性支持必填（`required`）、枚举（`enum_code` + `meta_enum`）、继承（`inheritable`，沿祖先向上取并集）；
- 归属记在 `doc_master.class_id`，属性值记 `plm_object.ext_json.classAttrs`；
- 写入集中在 `DocClassService`（删分类有"无子分类、无对象"保护）。

## 选项

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（采纳）** | 直接复用 `doc_class` 既有的 **`entity_code`** 作为对象类型维度（**无需新增列**），`item_master.class_id` 承载归属，`ext_json.classAttrs` 承载属性值 | 零重复实现；分类树/属性/继承/检索一套代码；表结构与文档侧对称 | `item_master` 加列；`DocClassService` 需参数化对象类型与计数表；类名/表名带 `doc` 字样（命名债） |
| B | 新写 `item_class` / `item_class_attr` 全套 | 零改动文档模块 | 两套同构代码与页面，违反 R2（单一口径），后期双份维护 |
| C | 抽公共分类内核（通用 `classify_*` 表，doc/item 都迁移过去） | 最干净、长期最优 | 动到已验收的 P2 模块与存量数据，工作量最大，与当前进度不匹配 |

## 决策

采纳 **A**。理由：`entity_code` 已经是天然的第二维，不需要新增列就能隔离开零件与文档分类；B 直接违反"单一事实源"，C 的收益（命名整洁）不足以抵消动 P2 存量数据的风险。
A 的落地形态与 C 一致（都是"一套表 + 对象类型维度"），将来若要演进到 C，只需把 `doc_class` 改名/迁表，不动业务语义。

## 影响

- **表**：`item_master` 加 `class_id`（V71）+ 索引；`doc_class`/`doc_class_attr` 不新增列（复用 `entity_code`）。
- **服务**：`DocClassService` 参数化对象类型（`tree/create/findByCode/requireClass/counts/delete`），成为两张分类表的**唯一写入口**；文档侧调用签名不变（旧方法保留为委派）。
- **接口**：新增 `/api/v1/item-classes/**`（树与属性，维护需 `pse.classify.manage`，查看用 `pse.item.read`）与 `/api/v1/items/{id}/classify`（归类 + 读取）；`/api/v1/items` 增加 `classId/includeChildren` 与 `attr.<code>` 过滤。
- **权限**：新增 `pse.classify.manage`（对应蓝本 `ModuleName=Classify` 维护档）；查看沿用 `pse.item.read`。蓝本的**部门授权 `PERGROUP`** 首版不做 → `GAP(T-H-01)`。
- **数据**：属性值落 `plm_object.ext_json.classAttrs`，与批次 G 的 ERP 客制字段（平铺键）**互不覆盖**：`ItemService.buildExt` 以既有 `ext_json` 为底，嵌套键原样保留。
- **命名债**：`DocClassService` / `doc_class` 名称仍带 `doc`，但语义已是"对象分类"。不改名以降低改动面，已在类注释与本文记录。

## 回滚

1. 代码回滚到 V71 之前；
2. 数据侧可保留 `item_master.class_id`（空列无副作用）与 PdmItem 分类行（`doc_class.entity_code='PdmItem'`，与文档分类互不影响）；若要彻底清理：`DELETE FROM doc_class_attr WHERE class_id IN (SELECT id FROM doc_class WHERE entity_code='PdmItem')` 再 `DELETE FROM doc_class WHERE entity_code='PdmItem'`，并 `DROP INDEX idx_item_master_class`。
