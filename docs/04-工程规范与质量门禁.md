# 五、工程规范与质量门禁

## 1. 仓库与分支

- 主干 `main` 常绿；功能分支 `feature/<阶段>-<简述>`；修复 `fix/<简述>`；发布打 tag `v0.x.0`。
- 提交信息（Conventional Commits，中文描述）：
  ```
  feat(pdm): 支持文档检出超时自动释放
  fix(iam): 修正组织子树数据范围漏算
  docs(plan): 补充 P6 工艺卡片验收标准
  ```
- 提交前必须：本地 `mvn verify` 与 `pnpm lint && pnpm build` 通过；Husky + lint-staged 拦截。
- **禁止**：提交密钥/密码、提交 `target`/`node_modules`、提交 IDE 私有配置、直接推 `main`（走 PR/自查清单）。
- 提交与推送由负责人执行；自动化代理不得擅自 commit/push。

## 2. 包结构与命名

```
com.nexplm.<module>.<layer>
  api          Controller / DTO / Assembler（仅编排与校验）
  app          应用服务（事务边界、跨聚合编排）
  domain       聚合/实体/值对象/领域服务/领域事件（不依赖 Spring）
  infra        Mapper / Repository 实现 / 外部适配器
  support      模块内工具
```

命名：
- 类：`PascalCase`；方法 `camelCase`；常量 `UPPER_SNAKE`；数据库 `snake_case`。
- 接口无 `I` 前缀；实现 `XxxImpl`；DTO 后缀 `Req/Resp/Dto`。
- 领域事件过去式：`DocumentReleasedEvent`；命令式方法：`release()/checkout()`。
- 错误码：`<模块>.<场景>.<原因>`，如 `PDM.CHECKOUT.ALREADY_LOCKED`，集中定义在 `ErrorCode` 枚举。

## 3. 分层规约（强制）

1. Controller 不写业务逻辑，不直接注入 Mapper；
2. 领域层不出现 `@Service/@Autowired` 之外的框架类型；领域方法不返回 DTO；
3. 跨聚合只通过应用服务或领域事件，不直接改对方表；
4. 状态字段只能由 `LifecycleService`/`PhaseService`/`WorkflowSyncService` 写入，
   其他任何 UPDATE 该字段视为违规（用 ArchUnit 规则拦截）；
5. 查询返回必须显式列白名单，禁止 `SELECT *`（MyBatis 用 `resultMap` 明确列）；
6. 每张表只允许一个 Mapper 写入（归属模块唯一）。

## 4. 数据库规约

- 迁移脚本只增不改（已上线的 `V*.sql` 不得修改），命名 `V<序号>__<描述>.sql`；
- 每张表必须有主键、`created_at`；业务表必须有 `version`（乐观锁）；
- 索引命名 `idx_<表>_<列>`，唯一 `uk_<表>_<列>`，外键 `fk_<表>_<引用表>`；
- 禁止在数据库层写业务逻辑（触发器/存储过程），复杂计算放应用层；
- 大表分页必须走键集分页（`WHERE id > ? ORDER BY id`），禁止深 offset。

## 5. 测试策略

| 层 | 工具 | 覆盖要求 |
|---|---|---|
| 单元 | JUnit5 + AssertJ + Mockito | 领域服务/状态机/规则求值/版本格式化 ≥ 70% 行覆盖 |
| 集成 | Testcontainers(PG/Redis/MinIO) | 每个 Mapper 的关键查询、事务、乐观锁冲突 |
| 契约 | springdoc + REST Assured | 每个开放接口的成功/失败/越权三态 |
| E2E | Playwright | 每阶段主流程 1~3 条脚本 |
| 性能 | JMeter/Gatling | BOM 展开、列表、批量导入、并发审批 |
| 安全 | OWASP ZAP + 自写越权用例 | 每阶段回归 |

测试数据：统一用 `src/test/resources/fixtures/*.sql` 或 Testcontainers 初始化脚本，禁止依赖手工数据库。

## 6. 代码质量门禁

- 静态：SpotBugs / Checkstyle / ArchUnit（分层与状态写入规则）/ ESLint + vue-tsc；
- 复杂度：单方法圈复杂度 ≤ 15，单类 ≤ 500 行（超出需说明）；
- 重复：新增重复代码块 ≤ 3%；
- 依赖：`mvn dependency:analyze` 无未使用依赖；CVE 扫描（OWASP Dependency-Check）无高危；
- 覆盖率：新增代码行覆盖 ≥ 70%，整体不低于 60%。

## 7. API 规范

- 路径：`/api/v1/<模块>/<资源复数>`；动作型接口用子资源或 `:action`，如 `POST /api/v1/documents/{id}:checkin`；
- 方法语义：GET 查询、POST 创建/动作、PUT 全量更新、PATCH 局部更新、DELETE 删除；
- 响应统一：
  ```json
  {"code":"OK","message":"成功","data":{...},"traceId":"..."}
  ```
  错误：`{"code":"PDM.CHECKOUT.ALREADY_LOCKED","message":"该对象已被 张三 检出","data":null,"traceId":"..."}`
- 分页：`?page=1&size=20&sort=updatedAt,desc`，响应 `{items,total,page,size}`；
- 时间：ISO-8601 带时区；ID 一律字符串（防前端精度丢失）；
- 幂等：写接口支持 `Idempotency-Key`；
- 版本：破坏性变更升 `/api/v2`，旧版保留至少一个小版本周期。

## 8. 安全规约

- 密码：Argon2id；登录失败 5 次锁定 15 分钟；管理员强制改密策略；
- 令牌：access 30min、refresh 7d 且轮换（旧 refresh 立即失效）；敏感操作二次校验（可选）；
- 文件：扩展名白名单 + MIME 校验 + 大小限制 + 病毒扫描；下载走预签名，不暴露真实路径；
- 输入：所有 SQL 参数化；富文本用白名单过滤（jsoup）；导出防 CSV 注入；
- 日志：禁止打印密码/令牌/完整身份证；个人信息脱敏；
- 越权：每个接口必须有"他人资源"用例（P0 级用例）。

## 9. 文档要求

- 每个模块 `docs/modules/<module>.md`：职责、表、接口、状态机、权限点、常见问题；
- 元数据字典由系统导出（`/api/v1/meta/export`），随版本归档；
- 变更需更新 `CHANGELOG.md`；
- 架构级决策写 ADR（`docs/adr/NNNN-*.md`）。
