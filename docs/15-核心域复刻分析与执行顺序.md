# 核心域复刻分析与执行顺序（编码 · 物料/零部件 · BOM）

> 定位：用户要求「先做最基础的四域，结合蓝本与 `TCPLM` 分析后复刻」。
> 本文是**分析结论 + 执行顺序**，不是进度台账（台账仍在 `docs/03`）；蓝本结构见 `docs/13`，分类数据见 `docs/14`。
> 所有蓝本数据均为**只读**取证（`SELECT` / `sys.*`），未对 `TCPLM` 做任何写入。

## 一、结论摘要（先看这五条）

1. **蓝本编码 = 「编码种类」+「码段树」+「码值」+「分类绑定路径」四层**（`EXP-20261108-44` 以
   `CODEKIND`/`CODERULE`/`CODEVALUE`/`CODEVALUETOVALUE` + 分类路径取证，截图亦印证）：
   - `CODEKIND`(17)：元器件 / 成品 / 原材料 / 外购标准件 / 请购单 / 变更单 / 制造规范… 每个种类有自己的**码段树**；
   - `CODERULE`(58)：码段（`大类` ord=1 / `小类` ord=2（`PARENTCODERULE=大类`）/ `流水码` ord=3, `LENGTH=5` /
     `年份`/`顺序号`/`地域代码`/`请购单`…），`LENGTH` 定长、`CODEDROPMODE=DropDown` 表示从码值下拉选；
   - `CODEVALUE`(1,170)：码值（`1001`=断路器、`02`=抽出式框架断路器、`*`=流水通配），`PARENTVALUE` 构成码值树；
   - **`CLASSIFYCLASS.CLASSCODEPATH`** 才是绑定点：4 段 `[种类] ; [码值1] ; [码值2] ; [*]`，
     UI 上显示为「**关联编码：元器件编码规则/1001/02/\***」（见用户提供的分类管理截图）；
   - 取号 = 按分类路径拼接码值 + 该规则流水段自增 → `1001` + `02` + `00001` = **`10010200001`**。
   - **同一棵分类树下不同分类可绑不同种类**：`100102 抽出式框架断路器` → 元器件规则；
     `110101 板材` → **原材料规则**；`120405 其它` → **外购标准件规则**（各自流水段也不同）。
   - **264 个分类里只有 258 个有 `CLASSCODEPATH`**，6 个（`2001 非标自制件`、`2002 通用自制件`、`CH001 产号`、
     `DYCPSYB`…）**没有绑定 = 不自动取号**（人工/图号）——这才是 5.3% 例外的真因。
   > ⚠ 两次修正：① 最早"人工/图号为主"错；② 后来"编码 = 分类码 + 流水"只是**观测到的现象**
   > （分类编码恰好等于码值拼接），不是机制。真实机制是「分类绑种类 + 各码段取码值 + 流水段自增」。
2. **物料主数据字段已经做过一轮**（`V70`）：物料 14 个 ERP 缺口通过 `meta_field` + `ext_json` 补齐（`FErpClsID`/`FCategoryID`/`FIsProduce`…），另有 `item_design_attr`（13 列）承载设计属性。**不要重复造字段**。
3. **真正的缺口在「编码路由 / 发放流水 / 人工编码校验」和「BOM 数量与类型」**——这四项是纯后端、可独立交付、且是上层（物料/BOM/ERP 下发）的基础。
4. **11 类物料当前共用一条 `PdmItem` 编码规则**（`ItemService.resolveCode` 写死），改规则对所有类型一起生效——这是「物料编码管理」最直接的缺口。
5. **BOM 只用了 `Design` 视图 + `Quote` 类型**（蓝本 79,105 行全是这一组合），所以「BOM 三视图」在新系统已够用；缺的是**行字段**（数量四兄弟、BOM 类型、工序路线、数据来源）。

## 三、逐域对照与差距

### 3.1 编码管理

> **编码组成（2026-11-08 口径纠正，`EXP-20261108-47`）**：
> `10050101076` = 大类 `10`（2 位）+ 中类 `1005`（4 位，含大类前缀）+ 小类 `100501`（6 位，含中类前缀）+ 流水 `01076`（5 位）。
> 三段前缀**层层包含**，不是并列相加；`code_segment_value` 里 `1005` 是**中类**、`01` 是**小类的后 2 位**。
> 因此完整码 = 小类码（6 位）+ 流水（5 位）= 11 位。

| 能力 | 蓝本 | 新系统 | 状态 |
|---|---|---|---|
| 规则模型 | **三层**：`CODEKIND`(17) → `CODERULE`(58 码段，树) → `CODEVALUE`(1,170 码值，树) | `code_rule` 单层 `segments_json`（段类型 `TEXT/DATE/CLASS/SEQ`） | **缺"种类/码段/码值"三层** |
| 分类绑定 | `CLASSIFYCLASS.CLASSCODEPATH` = 「种类 + 码值链 + 流水通配」，如 `元器件编码规则/1001/02/*`（258/264） | `doc_class.code_rule_code`（只绑一条规则，**无码值**） | **缺码值路径**（T-CORE-08） |
| 按分类取号 | 按绑定路径拼接码值 + 该规则流水段自增 | T-CORE-07：`CLASS` 段 = 分类**编码**，仅在"分类码 = 码值拼接"时正确（258 条里绝大多数如此，但机制不对） | **需改为按路径渲染** |
| 流水 | 每种规则的流水段独立（`*` 码值），按分类分别计数 | `code_sequence(rule_code, scope_key=分类)` | 计数口径已对，规则维度需扩 |
| 按类型路由 | 按「对象类型 + 编码种类」 | `PdmItem:<itemType>` 路由，无专属规则回退 `PdmItem`（T-CORE-01） | 已补齐（但种类维度未接） |
| 发放流水 | `CODERES` 60,300（`CODES`/`ORDINAL`/`CODEKINDID`/`GENERATORPATH`） | `code_issue`（T-CORE-02） | 缺 `CODEKINDID`/`GENERATORPATH` |
| 人工编码 | `MaxOrderCodeLength=9` + `CodeMachineDenyChar` | `nexplm.coding.manual-pattern`（T-CORE-01） | 已补齐 |
| 权限 | `CODEPERMISSION`(78) 按种类授权（`CODEVALUEPERMISSION` 空） | `system.coding.read/manage`（V74） | 细粒度待业务（B20） |

### 3.2 物料/零部件主数据

| 能力 | 蓝本 | 新系统 | 差距 |
|---|---|---|---|
| 类型 | 11 类（`ITEMTYPE`） | 8 类枚举（产品/部件/零件/标准件/工装/量具/模具/外购件） | 蓝本的 CIS/服务/废料/外协/手工单未建枚举 |
| 核心字段 | `PSEBASEFORM` 51 列 | `item_master` 13 列 + `item_design_attr` 13 列 | 覆盖约 26 列 |
| 金蝶客制 | 23 个 | `V70` 已补 12 个 `meta_field`（`ext_json`） | 已实现，注意别重复 |
| 分类 | `CLASSIFYRELATION` | `item_master.class_id`（单分类） | 66 件多分类差异（`docs/14`） |

### 3.3 BOM

| 能力 | 蓝本 | 新系统 | 差距 |
|---|---|---|---|
| 行字段 | `PSEBOMLINE` 37 列 | `bom_line` 18 列 | **缺数量四兄弟、BOM 类型、工序路线、数据来源、10 个客制** |
| 数量 | `TOTALQTY/USEQTY/SURPLUSQTY/SUBUSEQTY` | `qty` + `loss_rate` | 语义不同（蓝本是"总用量/单台用量/剩余/子用量"） |
| 视图 | `PVIEWTYPE=Design` | `view_type`（DESIGN/…） | 够用 |
| 类型 | `LBOMTYPE=Quote` | 无独立类型 | **缺** |

## 五、明确不做

1. **不把 11 类物料都改成自动取号**：蓝本实测大量人工/图号编码，强行统一会改变现场习惯（违反 R4 不静默改语义）。
2. **不重建 `CODERULE` 的码段树模型**：新系统整规则 + `segments_json` 已能表达，粒度差异不影响现场使用（B19 已收口 16 个对象）。
3. **不加 BOM 的「制造/装配」类型分支**：蓝本实测只有 `Quote`，加了是无用复杂度。
4. **不重复补 `V70` 已覆盖的 12 个金蝶客制字段**。

- `PSEBOMLINE$`（253,829）是否等价于版本快照——**待验证**。
- 蓝本 `Coding.setting` 的 `CodeMachineDenyChar`（跳码禁用字符）具体字符集——**待取证**（`Config/Coding.setting` 可读）。
