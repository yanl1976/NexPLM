# 三、数据模型设计

> 数据库：PostgreSQL 16 为主，MySQL 8 / 达梦 / 金仓为兼容目标。
> 约定：表名小写下划线；主键 `bigint`（雪花，`AssignedIdGenerator`）；时间统一 `timestamptz`；
> 业务时间戳（旧系统 LONG）统一换算为 `timestamptz`；布尔 `boolean`；枚举存字符串码；
> 所有表带 `created_by/created_at/updated_by/updated_at`（由 MyBatis 拦截器自动填充）；
> 逻辑删除仅用于可恢复对象（`deleted boolean`），审计与流水表不删。

## 1. 分层

```
① 平台元数据    meta_entity / meta_field / meta_relation_type / meta_enum / meta_form / meta_menu / meta_lifecycle
② 身份与权限    sys_company / sys_org / sys_user / sys_role / sys_group / sys_permission / sys_acl_entry / sys_permission_rule
③ 业务对象通用  plm_object / plm_relation / plm_state_log / plm_checkout
④ 领域子表      doc_master / pse_item / pse_bom_line / cm_change / capp_process / prj_project / prj_task / qm_problem ...
⑤ 文件        file_object / file_link
⑥ 编码        code_rule / code_sequence / code_history
⑦ 流程        wf_binding（Flowable 自带 ACT_* 表）
⑧ 集成        itg_endpoint / itg_mapping / itg_job / itg_log
⑨ 审计        sys_audit_log / sys_audit_anchor / sys_signature / sys_login_log
```

## 4. 业务对象通用表

### 4.1 `plm_object`

```sql
plm_object(
  id             bigint PK,
  object_type    varchar(64)  NOT NULL,
  master_id      bigint       NOT NULL,   -- 版本族
  code           varchar(128) NOT NULL,
  name           varchar(500) NOT NULL,
  company_id     bigint       NOT NULL,
  org_id         bigint,
  owner_id       bigint,
  owner_group_id bigint,
  security_level smallint     DEFAULT 0,
  lifecycle_state varchar(32) NOT NULL,
  phase_state     varchar(32),
  workflow_state  varchar(16) DEFAULT 'NONE',  -- NONE/RUNNING/APPROVED/REJECTED/CANCELED
  revision       int          NOT NULL DEFAULT 1,
  iteration      int          NOT NULL DEFAULT 1,
  is_latest      boolean      NOT NULL DEFAULT true,
  released_at    timestamptz,
  obsolete_at    timestamptz,
  ext_json       jsonb        NOT NULL DEFAULT '{}',
  version        int          NOT NULL DEFAULT 0,  -- 乐观锁
  deleted        boolean      NOT NULL DEFAULT false,
  created_by, created_at, updated_by, updated_at
)
UNIQUE (object_type, code, revision, iteration) WHERE deleted = false
INDEX  (object_type, company_id, lifecycle_state, is_latest)
INDEX  (master_id), (code), (owner_id), (updated_at DESC)
GIN    (ext_json jsonb_path_ops)
```

规则：
- `master_id` 首次创建时 = `id`（自引用）；
- 新 Revision：复制主记录 + 子表 → `revision+1, iteration=1`，旧记录 `is_latest=false`；
- 新 Iteration：仅 `iteration+1`，旧记录 `is_latest=false`；
- `code` 在同族内不变（编码器按 revision 规则可加后缀，由元数据声明）。

## 11. 索引与性能策略

1. 列表默认查询条件必须命中 `(object_type, company_id, is_latest, deleted)` 复合索引；
2. 高频扩展字段（如 `ext_json.drawingNo`）由 `meta_field.indexed` 生成表达式索引；
3. 审计表月分区 + 保留策略（默认 24 个月，可归档到冷表）；
4. BOM 递归查询使用 `MATERIALIZED` CTE + 深度限制（默认 50 层，防环）；
5. 禁止在业务代码中 `SELECT *`；列表 DTO 显式列白名单；
6. 大字段（`schema_json`、`layout_json`、`before_json/after_json`）独立存储避免宽表膨胀。

## 12. 数据完整性

- 外键：核心关系（子表→`plm_object`、`file_link→file_object`）建 FK；跨域弱引用不建 FK，改由应用校验 + 定期巡检任务。
- 唯一约束：`plm_object(object_type, code, revision, iteration)`、`file_object(sha256)`、`code_sequence(rule_code, scope_key)`。
- 一致性巡检任务（每日）：孤立子表记录、`is_latest` 多真、流程态与生命周期态冲突、文件引用计数偏差、编码重复。
