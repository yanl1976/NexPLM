# UI 风格分析与融合方案

> 背景：新系统首版直接用 Element Plus 默认观感，工程师反馈"很难看、根本没法使用"——本质不是丑，
> 而是**密度和视觉语言不对**：PLM 是工程师的高密度工作台，不是中台 Demo。
> 本文基于两个真实来源做对照，先定设计令牌，再改实现。
>
> 来源 A：旧系统蓝本 `PLMSOFT/`（静态资源反推）
> 来源 B：`docs/天水电气传动SIPM PLM解决方案.pdf` 的界面截图（已渲染到 `docs/assets/ui-ref/sipm/`）

## 一、两个来源的事实

### A. 旧系统 PLMSOFT（无整屏截图，从样式/控件/页面 XML 反推）

| 证据 | 内容 |
|---|---|
| `PLMSOFT/Server/Base/Css/BasePage.css` | `font-family: 微软雅黑…`、`font-size: 12px`；主色 `#479CD1`；hover/选中浅蓝 `#D8F0FC`；编辑/高亮浅黄 `#FFFFCC`；边框 `#CCCCCC`；禁用 `#c6c6c6` |
| `PLMSOFT/Server/Base/Ctrls/`（59 个控件目录） | `Grid / EditGrid / EditTreeGrid / BomTreeGrid / FilterGrid / Tree / VirtualTree / Tabs / SideTabs / VerticalTabs / WorkBenchNav / DashBoard / PageBoard / GanttTimeline / HtGantt / Dialog / RightMenu / MenuToolbar / BreadcrumbNavigation / ThreeStateTips / ProcessChar / PDFView / SView / QRCode` |
| `PLMSOFT/Server/InforCenter/Config/Pages/MainFlat.page` | `LayoutContainer(type=vertical)` + `CustomerContainer` 动态加载模板 → 桌面式窗口布局（不是响应式网页） |
| `PLMSOFT/Server/InforCenter/Config/Pages/HomePageContents.page` | 工作台由 `Tabs + LayoutContainer` 组成（内容块按页签组织，动态加载） |

**结论**：经典 WebForms 风格——**12px 字号、密集表格、左树 + 多页签、工具栏图标、右键菜单、三态提示**，圆角几乎为零，信息密度优先。已具备看板/甘特/三维查看等高级控件（说明"专业感"来自控件密度，不是装饰）。

> 待验证：上述是从 CSS/控件清单/页面 XML 反推的**样式与结构**结论，没有旧系统运行截图可对照视觉细节（配色比例、图标风格）。

### B. SIPM 方案截图（`docs/assets/ui-ref/sipm/`）

| 图 | 可复用的做法 |
|---|---|
| `p11.png` | 客户端主界面：深蓝标题栏 + 一排图标工具栏 + 左侧树 + 中间密集表格（列多、行矮）+ 右侧属性页签；字段自定义是"表格式行内编辑" |
| `p29.png` | **顶部品牌条 + 全局快捷入口**（待办事项 / 报警任务 / 逾期任务 / 发送消息 / 新消息 / 在线用户）；左树 + 多页签，每页签一张密集表 |
| `p35.png` | **BOM 变更对比：左右并排 + 黄底高亮 + 红绿字**，页面上直接标注"颜色区分差异，更直观" |
| `p51.png` | 项目监控：**红黄绿灯 + 文字**（正常 / 延误 / 超期 / 进度控制）而非彩色大标签；下部甘特图用「蓝色计划条 + 黄色当前进度」两色对比 |
| `p55.png` | 左侧竖排图标导航；表格状态列是**绿色圆点 + "正常"**，不是填色块 |

**结论**：SIPM 与旧系统同属"工程软件"家族，但补了三点旧系统没有的东西——**全局快捷入口**、**状态用灯/点 + 文字**、**差异目视化（并排 + 黄底 + 红绿）**。

### C. 新系统现状（问题定位）

| 现状 | 后果 |
|---|---|
| Element Plus 默认：正文 14px、卡片 8px 圆角 + 阴影、内边距 16~20px | 一屏只能看到 10 行左右数据，工程师要不停滚动 |
| 侧栏 220px 纯文字菜单，无图标分组、无待办/逾期入口 | 首屏看不到"我今天要干什么"，与 PLM 的待办驱动工作方式不符 |
| 状态一律用彩色 `el-tag` 平铺 | 列表里颜色噪声盖过信息，且无法区分"正常/延误/超期"的紧急度 |
| 表格行高 ~40px、斑马纹 + 全边框 | 视觉变重，扫描效率低 |

## 二、设计令牌（融合后）

| 维度 | 取值 | 来源/理由 |
|---|---|---|
| 正文 / 表格 / 表头字号 | 12px / 13px / 12px | 旧系统 12px 基准；表格比正文大半档便于扫读 |
| 字体 | `"Microsoft YaHei", "PingFang SC", "Noto Sans SC", sans-serif` | 旧系统微软雅黑，中文工程环境通用 |
| 主色 | `#1F5C8B`（hover `#2E76AE`） | 介于旧 `#479CD1` 与 SIPM 深藏蓝之间，偏沉的工程蓝 |
| 选中/悬停底 | `#D8F0FC` / `#F5FAFE` | 沿用旧系统浅蓝（老用户肌肉记忆） |
| 顶部品牌条 | 44px，`#1B3A57 → #24557D` 渐变 | SIPM p29/p51 品牌条 |
| 侧栏 | 200px，底 `#F7F9FB`，选中 `#D8F0FC` + 左 3px 主色条 | 旧系统浅色导航；不用深色避免与顶栏重复 |
| 边框 | `#DDE4EC`（1px），表格头底 `#EEF2F6` | 细线替代阴影 |
| 圆角 | 2px（卡片/输入/按钮），状态点除外 | 两者都近直角 |
| 表格行高 | 28px（紧凑），表头 30px | 一屏可见行数 ≥ 16 |
| 间距梯度 | 4 / 8 / 12 | 旧系统紧排 |
| 状态语义 | 正常 `#2E9E5B` / 进行 `#1F7AC0` / 延误 `#E6A23C` / 超期阻塞 `#D64541` / 归档 `#8A94A6` | SIPM 红黄绿灯 + 色点文字 |
| 差异高亮 | 底 `#FFF8D6`，新增绿 `#2E9E5B`，删除红 `#D64541` | SIPM p35 并排对比 |
| 阴影 | 仅弹窗/抽屉使用，卡片一律 1px 边框 | 减少"卡片墙"观感 |

## 三、页面级规范

1. **列表页**：`PageHeader`（标题 + 面包屑 + 主操作，44px）→ 筛选条（单行内联，控件宽 160~220px，右侧批量操作）→ 表格（首列固定、操作列右固定、单行省略 + tooltip、无斑马纹）→ 分页右对齐。
2. **主从页**：上主表 / 下明细页签（沿用旧系统 Tabs 习惯）；属性页用两列 `label 88px + 值`，不要一行一个大卡片。
3. **对比页**：并排两栏 + 差异行黄底 + 红绿字（BOM/变更对比必须这样做，不能只列一行摘要）。
4. **看板页**：指标卡内边距 10~12、数字 24px、标签 12px、无阴影；一屏 6~8 张；趋势用表格式热力（不引入图表库）。
5. **弹窗/抽屉**：宽 520 / 720，表单 label 88px，垂直间距 8；抽屉优先于整页跳转。
6. **移动端**（`/m/*`）不受紧凑令牌影响：`max-width: 768px` 时字号回到 14px、行高 36px，保证触控可用。

## 五、验收标准（可量化）

- 1920×1080 下，列表页首屏**数据行 ≥ 16**（现状约 10）；
- 页面内无 >14px 的正文字号；卡片圆角 ≤ 2px、无投影；
- 列表中的状态一律 `StatusDot`（色点 + 文字），不再用满屏彩色 tag；
- 顶栏在首屏可见「待办 / 逾期」入口，点击可直达；
- 移动端（≤768px）字号 ≥14px、行高 ≥36px，不因紧凑令牌变得难点。
