# 四、分阶段实施计划

> 节奏：2 周一个迭代；每阶段结束产出**可演示的纵向切片** + 该阶段 DoD 全绿。
> 人力口径：`2 人` = 1 后端 + 1 前端并行；单人全栈周期按 ×1.6 估算。
> 依赖关系：P1 是全部阶段的前置；P2/P3 可并行；P4 依赖 P1；P5 依赖 P2+P3+P4；P6 依赖 P3；P7 依赖 P2+P4；P9 依赖 P3+P6。

---

## P0 工程基线（1.5 周）

**目标**：任何人 `git clone` 后 10 分钟内跑起前后端与依赖，CI 可跑通。

任务：
1. 仓库与目录（docs/backend/frontend/deploy）、`.gitignore`、`.editorconfig`、许可证；
2. 后端骨架：Maven 多模块、Spring Boot、统一响应 `Result<T>`、全局异常、错误码枚举、参数校验；
3. 鉴权骨架：Spring Security + JWT（access 30min / refresh 7d，刷新令牌轮换）、密码 Argon2id；
4. 审计切面 `@Audit` + `traceId`（MDC）+ 结构化日志（JSON）；
5. Flyway `V1__baseline.sql`（元数据/身份/对象/文件/编码/审计表）与 `V2__seed.sql`（管理员、内置角色、字典）；
6. springdoc-openapi + 统一错误响应规范；
7. docker-compose（PG/Redis/MinIO/RabbitMQ）+ `deploy/README`；
8. 前端壳：Vite + Vue3 + TS + Element Plus + 登录页 + 主框架（侧栏/顶栏/多页签）+ 路由守卫 + 请求封装（token 刷新）；
9. CI：后端 `mvn verify`、前端 `pnpm build` + ESLint。

DoD：`mvn spring-boot:run` 起得来；`/actuator/health` 200；登录拿 token 调 `/api/v1/me` 成功；前端登录后进入首页；CI 绿。

## P1 平台内核 I：组织 / 权限 / 元数据（4 周）

**目标**：能"零代码"定义一个对象类型并在界面完成增删改查与授权。

任务：
1. 组织架构：公司/部门/组/用户/角色 CRUD、树拖拽、用户导入（Excel）、组织隔离与共享配置；
2. 功能权限：权限点注册表（启动扫描 `@RequiresPerm` 与 `sys_permission` 对齐，缺失报错）、角色授权界面；
3. 数据隔离：`@DataScope` 拦截器（company / org subtree / isolation / owner），单测覆盖各组合；
4. ACL：对象实例授权、批量授权、转交所有权、到期自动失效任务；
5. 规则权限：条件树模型 + `RuleEvaluator` + 规则设计器（前端可视化）+ 试算器；
6. 元数据引擎：
   - 实体/字段/枚举/关系 定义与发布（含校验、版本快照）；
   - 自动建表（扩展字段除外）与子表注册；
   - 元数据缓存（Redis + 本地 Caffeine 二级）；
   - `MetaController`：`/api/v1/meta/entities`、`/fields`、`/enums`、`/forms`；
7. 动态表单渲染（前端 `BizForm`）：31 种值类型的控件映射 + 必填/只读/联动/校验；
8. 生命周期设计器（状态/迁移可视化）+ 状态机服务 `LifecycleService`（命令式，唯一写入口）；
9. 字典与参数：枚举维护、系统参数（Int/Bool/Enum）、多语言；
10. 审计查询界面 + 操作日志（含对象变更前后差异）。

DoD：
- 在系统管理中新建 `示例对象`（3 字段，含枚举与日期），发布后自动出现在菜单，可新增/编辑/查询/删除；
- 给角色分配功能点后，未授权用户看不到菜单且后端 403；
- 规则权限：配置"仅本人可编辑"，A 编辑 B 的对象失败并留审计；
- 生命周期：配置 `草稿→已发布`，非法迁移被拒绝且记录状态日志。

## P2 文件仓 + 图文档 PDM（5 周）

**目标**：完整跑通"创建文档 → 检出 → 编辑 → 检入 → 审批 → 发布 → 版本回溯"。

任务：
1. 文件仓：MinIO 适配、分片直传、秒传（sha256）、预签名下载、病毒扫描钩子、孤儿清理任务；
2. 工作空间：我的/公共/组空间、文件夹树（path 枚举）、权限继承、拖拽移动、收藏、最近访问；
3. 图文档类型：普通文档 / CAD 文档两类起步（元数据 subtype），文档主文件与附件；
4. 检入检出：软锁、超时释放、强制解锁（审计）、检入生成新 iteration、版本历史对比（文件级 diff 摘要）；
5. 对象查看器页签：属性 / 文件 / 历史版本 / 关联对象 / 流程 / 权限 / 日志（元数据 `meta_tab` 驱动）；
6. 文档分类（Classify）：分类树、分类属性（继承/枚举/必填）、按分类建文档、分类检索；
7. 浏览：上传后触发转换（PDF/PNG），前端 `pdf.js` 预览；转换失败可见并可重试；
8. 全文检索：code/name/描述 tsvector + 高级查询（保存查询条件）；
9. 批量操作：批量下载（zip）、批量导入（Excel + 附件包）、批量授权。

DoD：
- 上传 200MB 文件断点续传成功，同文件二次上传秒传；
- 检出后他人只读且不能检入；管理员强制解锁留审计；
- 检入 3 次后版本 `A.1/A.2/A.3` 正确，可下载任意历史版本；
- 文档发布后普通用户不可编辑，走变更流程才能改（与 P4/P5 联动前用占位规则）。

## P3 零部件与 BOM（4 周）

**目标**：多类型零部件 + 多视图 BOM 树编辑 + 基线 + 替代件。

任务：
1. 零部件：8 种类型（产品/部件/零件/标准件/工装/量具/模具/外购件），类型特有字段（子表或 `ext_json`）；
2. 编码：接入编码器（零部件编码规则、唯一性校验、预占号）；
3. BOM 树：设计/工艺/制造三视图；节点增删改、拖拽调整序号、批量替换、批量修改用量；
4. BOM 校验：防环、重复子件、用量为 0、单位缺失、孤儿件；
5. 替代件与替代组（按旧系统 `ALTERNATESRELATION` 建模：独立关系表挂在被替换子件上，`PVIEWID` 限定局部/`ISGLOBAL` 全局、`ISTWOWAY` 双向、`PRIORITYLEVEL` 优先级；**不参与展开与汇总**，仅用于界面展示与「替换」操作）；
   有效性（旧系统两套并存：规则型 `PSEBOMLINE.LVALIDITYID → PSEVALIDITY/PSEVALIDITYDATA`、对象级 `DATEVALIDITY/UNITVALIDITY`；新模型收敛为 BOM 行日期区间 `effect_from/effect_to`，展开时按 `effectAt` 过滤，空区间=长期有效）；
6. 基线：创建/冻结/对比（结构差异高亮）；物料汇总三口径（**全层级按子件累计** / **仅叶子件**（旧 `CELLBOMSTATISTIC`）/ **逐行展开带层级路径**（旧 `FOWARDBOMSTATISTIC` 的 `LPATH`）），用量逐层累乘并叠加损耗率；
7. BOM 导出（xlsx，层级号 + 展开列，可直接回导）与导入（模板校验 + 差异预览后提交；沿用旧系统 `ImportBom` 的「层级号」方式，`PECODE` 父编号方式未实现；导入为**增量合并**，不删除文件中不存在的现有行；单位/有效期留空表示不改）；
8. 性能：10,000 行 BOM 展开 < 2s（递归 CTE + 缓存）。

DoD：
- 5 层 1 万行 BOM 展开与汇总均在 2s 内；
- 基线对比能准确列出"新增/删除/用量变更"；
- 拖拽调整 BOM 序号后持久化正确且并发冲突给出 409；
- 导入 5000 行 BOM 有差异预览与失败明细。

## P4 工作流 + 生命周期 + 电子签名（3.5 周）

**目标**：Flowable 落地，覆盖会签/加签/驳回/委托/超时/撤回。

任务：
1. Flowable 集成（嵌入式）、流程定义部署与版本管理、bpmn-js 设计器嵌入；
2. 业务绑定 `wf_binding`：按对象类型/条件自动选流程；
3. 执行人解析 SPI：用户/角色/组/组+角色/发起人/表单字段/项目角色；
4. 业务插件：`ChangeState`、`ChangePhase`、`SendNotification`、`ErpPublish`（骨架）；
5. 会签（多实例）、加签、驳回（指定目标节点）、撤回、委托（生效区间）、超时催办（定时器 + 消息）；
6. 我的待办/已办/我发起：分页与筛选，支持批量审批；
7. 电子签名：审批时对"对象版本 + 主文件 sha256"签名，签名块可在文档详情查看；
8. 流程与生命周期一致性巡检任务（每日）。

DoD：
- 一个 3 节点流程（发起→会签 3 人→归档）可完整走通，会签需全票；
- 驳回可回到指定节点，且对象状态随之回退；
- 委托在生效区间内自动转派；超时 24h 触发催办消息；
- 签名记录可验证文件未被替换。

## P5 变更管理（3 周）

**目标**：ECR/ECN 闭环 + 影响分析 + 追踪。

任务：
1. 变更申请（ECR）：类型（设计/工艺）、类别、原因、可行性、优先级、接收人；
2. 变更通知（ECN）与变更问题（Problem）；三者关联（申请→通知→问题）；
3. 关联对象：受影响（Affected）/影响（Impact）/参考（Reference），操作意图（修订/废弃/发布）；
4. 影响分析：从受影响对象出发，按 BOM 向上/向下、按文档引用关系，列出影响面（可导出）；
5. 变更执行：对 Affected 对象批量创建新 revision / 置为废弃，回写变更单；
6. 变更追踪视图（时间线：申请→评审→通知→执行→关闭）；
7. 阶段状态机：Apply/Notice/Problem 三套（元数据定义）。

DoD：一张 ECR 从提交到关闭全程可追溯；影响分析对 3 层 BOM 结果准确；执行后对象版本正确递增。

## P6 工艺 CAPP / MSE（6 周）

**目标**：工艺路线 → 工序 → 工艺卡片 → 资源 → 工时，可审批与导出。

任务：
1. 工艺路线：零件维度维护、批量编辑、路线串生成、适用性；
2. 工艺过程与工序：树形编排、序号重建、复制典型/现有工艺、工艺分工；
3. 工艺资源库：分类树 + 动态属性 + 查询条件保存 + 资源引用统计；
4. 工艺卡片：模板（表格结构定义：行/列/单元格合并）+ 数据绑定 + 富文本/图片 + 打印（PDF）与 Excel 导出；
5. 工艺成册与齐套性检查；
6. 工时定额：参数化公式、单件/批量工时、汇总；
7. 典型工艺库与复制；
8. 质量规划（简化版）：检验项/检验策略/控制计划表（表结构与导出）；
9. 与 ERP 的工艺下发接口预留（P9 实现）。

DoD：
- 一个零件的工艺路线 + 5 道工序 + 1 张工艺卡片可完整产出并导出 PDF/Excel；
- 卡片模板修改后历史卡片版式不串（模板版本化）；
- 工时汇总与工序工时一致，公式改动可重算。

## P7 项目与任务（4 周）

**目标**：项目模板 → WBS → 甘特 → 任务执行 → 交付物。

任务：
1. 项目：EPS 结构、立项、项目经理、计划起止、进度、状态；

5. 交付物：任务输入/输出对象（文档/零部件/工艺卡片），齐套性检查；
6. 工时填报与审批；项目资源负荷（简化）；
7. 项目门户：我的项目/项目经理/领导三视图（卡片 + 列表）。

DoD：从模板立项到任务完成、交付物齐套、进度自动汇总，全链路可演示；甘特拖拽后计划日期落库。
